# Яндекс Метрика

Счётчик: `113444344`. В интерфейсе Метрики вручную создайте шесть целей типа **JavaScript-событие** с идентификаторами ниже.

| Цель | Момент отправки | Локальный ключ защиты от повторов |
| --- | --- | --- |
| `auth_success` | Сессия успешно подтверждена после возврата из Яндекс ID или после тестового входа | Случайный ID попытки входа, созданный перед началом авторизации |
| `wizard_start` | Первое изменение поля в `useWizardForm.handleChange`, не открытие анкеты | Случайный ID попытки в sessionStorage; сохраняется при перезагрузке, сбрасывается вместе с анкетой |
| `wizard_complete` | Успешный ответ `createGenerationDraft` | draftId |
| `payment_start` | После создания платежа, непосредственно перед переходом на confirmationUrl | draftId |
| `payment_success` | Ответ API со статусом paid, reserved, consumed или generation_failed | draftId |
| `generation_success` | Операция consumed/success со storyId либо ответ polling генерации book/success | storyId, одинаковый для обоих источников |

`generation_failed` означает ошибку генерации после оплаты; цель успешной генерации при этом не отправляется. Возврат с ЮKassa сам по себе не подтверждает оплату. `payment_start` подтверждает попытку перехода, а не загрузку страницы ЮKassa.

Официальный асинхронный загрузчик находится в index.html. Автоматический просмотр отключён через defer; AppRoutes отправляет hit при изменении pathname. Повтор эффекта React не создаёт второй hit; возврат на страницу после посещения другой страницы создаёт новый просмотр. Перезагрузка страницы — новый просмотр, но не повтор бизнес-целей. Query и hash исключены, неизвестные пути заменяются на /404, referer содержит только предыдущий безопасный путь. Первый referer пустой. Заголовки страниц не собираются. Noscript-пиксель намеренно отсутствует: он обошёл бы очистку URL.

В reachGoal передаётся только название цели: без параметров анкеты, имён, фото, токенов, данных платежа или идентификаторов операций. ID используются исключительно в локальных ключах. Ссылки скачивания PDF исключены из trackLinks. Карта кликов отключена на анкете; webvisor выключен. HTTP Referer ограничен origin. Существующие маршруты статичны; /payment-return читает идентификатор операции из query. Проверка стороннего скрипта в реальном счётчике и его настроек остаётся необходимой перед выпуском: автоматические цели, сбор содержимого и другие возможности, включаемые в кабинете, не должны добавлять сбор персональных данных.

Механизма согласия на аналитику в приложении нет; новая система согласий не добавлена. Счётчик загружается сразу.

Отметки бизнес-целей записываются в localStorage до вызова ym. Это предотвращает повтор при polling, ререндерах, восстановлении операции и перезагрузке в том же браузере. Ошибка ym не влияет на приложение. Если постоянное хранилище недоступно, цель пропускается; если заблокирован скрипт, доставка не гарантируется. Повторной доставки нет. Очистка хранилища, другой браузер или одновременная гонка между вкладками не дают гарантии exactly-once. При первом обнаружении старой завершённой операции без локальной отметки цель тоже будет отправлена.

Если пользователь закрыл сайт, фронтенд не увидит последующее подтверждение оплаты/генерации. Для полного учёта минимальное отдельное серверное решение — отправлять эти две конверсии из существующих обработчиков подтверждения, сохраняя уникальную отметку (goal, operationId) и используя поддерживаемый Метрикой серверный механизм конверсий. Тогда источником этих двух целей должен стать сервер, чтобы не дублировать фронтенд. В текущей задаче API, БД и сервер не менялись.
