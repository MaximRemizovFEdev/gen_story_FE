# Авторизация frontend

Frontend использует серверную HttpOnly cookie-сессию и не хранит признак авторизации в `localStorage`.

## Пользовательский поток

- При запуске `AuthProvider` вызывает `GET /api/auth/me`.
- До завершения проверки защищённый интерфейс не отображается.
- Гость видит вход через Yandex ID; кнопка переводит браузер на `/api/auth/yandex`.
- Backend возвращает пользователя на `/auth/success` или `/auth/error`.
- Успешный маршрут повторно проверяет `/api/auth/me` и ведёт на `/`.
- Выход выполняется через `POST /api/auth/logout`; ответы `204` и `401` завершают локальную сессию.
- Любой `401` защищённого API очищает пользовательское состояние и останавливает активную генерацию без автоматического возобновления после входа.

## Локальная разработка

Vite проксирует `/api` на `VITE_DEV_API_TARGET` (по умолчанию `http://localhost:3000`). Чтобы показать кнопку development-входа, запустите Vite с:

```env
VITE_DEV_AUTH_ENABLED=true
```

Кнопка вызывает `POST /api/auth/dev-login`. Ответ `404` означает, что backend-запуск не разрешает development-вход. В production-сборке кнопка отсутствует независимо от флага.

## Production

Nginx передаёт `/api/*` сервису `backend:3000`, а остальные неизвестные пути возвращает на `index.html`, поэтому прямое открытие `/auth/success` и `/auth/error` работает как SPA navigation.

Владение книгами определяется только серверной сессией. Телефон может отображаться как необязательное поле профиля из `/api/auth/me`, но не передаётся в generation/library API и не включается в файловые URL.
