Проведи полный рефакторинг текущего React-кода.

Не меняй функциональность вообще. Пользователь не должен заметить никаких изменений. Изменить нужно только архитектуру.

Сейчас компонент Wizard нарушает практически все принципы разделения ответственности:

хранит всё состояние;
содержит бизнес-логику;
выполняет API;
рендерит все шаги формы;
содержит конфигурацию формы;
содержит валидацию;
содержит экран генерации;
содержит обработку ошибок.

Кроме того, в файле уже появился дублирующийся код и повторяющиеся блоки JSX.

Требуется

Разделить код на небольшие компоненты и хуки.

В результате:

Wizard должен стать координатором, а не местом, где реализована вся логика приложения.
Конфигурация шагов должна лежать отдельно.
Конфигурация вариантов выбора должна лежать отдельно.
Валидация должна быть вынесена в отдельный модуль.
Логика генерации книги должна быть вынесена в отдельный hook.
Логика работы с формой должна быть вынесена в отдельный hook.
Экран прогресса генерации должен стать отдельным компонентом.
Отрисовка шага анкеты должна стать отдельным компонентом.
Поля ввода должны быть переиспользуемыми компонентами.
Обязательно

Не менять:

API;
последовательность вызовов;
структуру запросов;
структуру ответов;
UX;
названия шагов;
отображение прогресса;
обработку ошибок;
кнопку "Повторить";
отображение обложки;
отображение PDF.

Все должно работать абсолютно так же, как сейчас.

Код должен соответствовать следующим требованиям
один компонент — одна ответственность;
минимум дублирования;
никаких JSX-функций по 300–500 строк;
никаких огромных switch/case;
никакой бизнес-логики внутри JSX;
никаких inline-конфигураций больших массивов;
функции должны быть короткими и читаемыми;
компонент желательно не более 150–200 строк;
удалить весь дублирующийся код, который появился после последних изменений;
итоговая структура проекта должна быть удобна для дальнейшего развития.

Важно: не переписывай приложение с нуля и не меняй поведение. Выполни именно рефакторинг существующего кода, сохранив всю текущую функциональность.
